# Room Chat Retrieval Evaluation v3

本目录是一套固定随机种子的中文合成聊天评测集，和 v2 分开保存。

## 数据规模

- 一个聊天室、一个会话，3,000 条按 seq 和时间递增的消息。
- 100 位虚构成员，聊天覆盖动画、影视、综艺、音乐、游戏和日常话题。
- 83 道测试题：30 道普通单证据题、30 道三证据题、8 道股票时间题、15 道无答案题。
- 股票话题在早、中、晚三个历史区间重复出现；时间题包含 4 道明确日期范围题和 4 道“最近一次”题。
- 30 道多证据题都需要 3 个不同证据块；各证据段落分布在不同历史区间。

## 文件

- `corpus.jsonl`：聊天消息，字段与项目 `ChatMessage` 接近。
- `queries.jsonl`：问题、参考答案和证据标注。
- `generate_dataset.py`：使用固定 seed 重新生成上述两个文件。

答案证据以 `gold_evidence_groups` 表示。每组用一个关键消息 ID 定位一个预期证据块，避免把 seq 当成检索指标。评测时应先通过项目当前的生产切分流程生成子块，再把组内锚点消息映射到实际子块 ID；单块题必须映射到 1 个不同子块，多块题必须映射到 3 个不同子块。子块级 Recall 以这些映射后的子块为单位计算。切分规则或模型变化后，应重新生成并审核映射。

多证据题分阶段报告：RRF 候选池按配置的 K 计算 Evidence Recall@K；最终 Top 3 计算 Evidence Recall@3、Complete Evidence@3 和逐证据 MRR@3。这样可以区分“正确块是否进入候选池”和“重排后是否仍留在最终结果”。

时间题在 `time_hint` 中标注预期的 `range` 或 `latest`。评测时应分别报告时间题在关闭时间排序和启用时间排序后的结果，并单独报告模型生成时间参数的准确率；时间范围按 Asia/Shanghai 计算。普通单证据题和时间题的单证据指标分开呈现，避免时间题被总体平均值掩盖。

无答案题使用未出现在语料中的作品名构造相近主题干扰题，回答字段为空；这类题单独统计是否错误召回或作答，不计入 Recall/MRR。

## 重新生成

```bash
python eval_data/room_chat_v3/generate_dataset.py
```

本数据为人工设计情境、程序生成背景闲聊的合成集，适合在同一条件下比较检索链路；结果不能直接代表真实聊天室分布。
