# v5 原始消息子块检索评测

本轮对当前原始消息索引链路评测，不生成答案，不使用 LLM 拆解用户问题。

## 数据与索引

- 输入：一个房间的 10,000 条合成消息、50 名发送者、200 道可回答题；其中 100 道带时间条件。
- 题目包含共 265 个标注证据组。评分时按每题的证据组覆盖比例取平均。
- 父块：最多 50 条消息或 2,000 字符，使用实际 `build_message_chunks` 切分。
- 使用 deepseek-flash 实际执行话题分组，共 326 个父块；没有沿用旧手工子块。
- 子块：话题与原始消息文本，最多 300 字符，配置 overlap 为 20；共生成 2,490 个子块。
- 模型：Qwen3-Embedding-0.6B、Qwen3-Reranker-0.6B，在 CUDA 上运行。
- Milvus：中文 BM25 与稠密向量混合检索，RRF 返回 10 个候选，预筛选 5 个进入重排，最终返回 3 个子块。
- 原始消息 ID 映射到新子块时，同时要求 seq 对应且子块正文包含答案原文。缺少索引的证据组数为 0。
- 为隔离检索评测，仅替换了已有父块的数据库查重操作，没有写入 MySQL 或请求 IM。

## 结果

| 题目范围 | 题数 | 时间因素关闭 Recall@3 | 时间因素开启 Recall@3 | 时间因素关闭 MRR@3 | 时间因素开启 MRR@3 |
|---|---:|---:|---:|---:|---:|
| 全部题目 | 200 | 62.08% | 75.58% | 0.5508 | 0.7117 |
| 时间题 | 100 | 56.00% | 83.00% | 0.3383 | 0.6600 |
| 无时间题 | 100 | 68.17% | 68.17% | 0.7633 | 0.7633 |

整体 Recall@3 增加 13.50 个百分点，MRR@3 增加 0.1608。时间题 Recall@3 增加 27.00 个百分点。

| 检索性能范围 | 平均耗时 | P95 |
|---|---:|---:|
| 全部题目，关闭时间因素 | 162.55 ms | 175.81 ms |
| 全部题目，开启时间因素 | 176.99 ms | 200.92 ms |
| 时间题，开启时间因素 | 189.76 ms | 206.94 ms |

索引向量化累计 28.50 秒，Milvus 写入累计 1.79 秒。应用模块导入后的本轮执行时间为 224.79 秒；这不包含 Python 依赖冷导入时间。检索耗时从调用检索函数到重排结束，不包含聚类、索引构建或最终答案生成。

无时间题两种条件执行路径相同，开启时间因素一列复用对应关闭结果，不重复计算。

## 评分定义与边界

- 每题证据 Recall@3 = 前三个子块覆盖的标注证据组数量 / 该题全部标注证据组数量。整体对 200 题取宏平均。某个证据被多个子块包含时，只计一次。
- MRR@3 = 第一个相关子块排名的倒数，前三名均不相关记为 0。它不表示多证据题的证据全部找齐。
- 每题都验证最终恰好返回 3 个互不重复的子块。指标已使用独立计算代码从 `results.jsonl` 复算。
- 时间范围来自数据集标注。时间开启条件同时使用当前代码中的时间预筛选和重排时间输入，没有评测 LLM 时间解析能力。
- 本轮复合问题直接作为原始查询检索，没有经过线上 Agent 的子问题拆解，不能将指标解释为完整 Agent 问答正确率。
- 数据为合成聊天，不代表真实线上分布。不能与使用旧手工子块、不同题目口径的历史数字直接比较。

## 产物与复现

- `config.json`：参数、数据哈希和相关源码哈希。
- `batches/`：逐父块构建检查点，保留本轮 LLM 实际分组后的子块。
- `child_chunks.jsonl`、`parents.json`：本轮生成的新索引材料。
- `evidence_mapping.json`：标注原文与新子块 ID 对应关系。
- `results.jsonl`：200 道题的两种时间条件、最终 Top3 正文、分数和证据对应。
- `summary.json`：汇总指标。

运行入口为上一级的 `run_raw_chunk_eval.py`。相同配置重跑会复用已完成的聚类检查点。临时 Milvus collection 已在本轮结束后删除，没有保留业务向量数据。
